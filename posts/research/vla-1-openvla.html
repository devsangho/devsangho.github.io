When you tell a robot "pick up the red cup," the model has to take the camera image and this sentence and output numbers saying how far to move the joints. This series follows how the way those numbers are produced changes across four models.

These are notes I put together while studying, and I rechecked the architectures and numbers against each original paper. Values I picked arbitrarily for explanation are marked as examples. One question runs through all four parts. In what form is the scene information understood by the VLM passed along, and how is it turned into continuous actions?

1Three Axes for Comparing the Four Models

When looking at VLA (Vision-Language-Action) models, it helps to consider three things separately: which VLM serves as the backbone, how actions are produced, and how much training and inference cost. The four models covered in this series look like this in a table.

ModelAction representation and generationKey characteristics
OpenVLADiscrete tokens, autoregressive generationUses a VLM directly as the robot policy
OpenVLA-OFTContinuous action chunks, parallel predictionFast fine-tuning and control
π0Flow matching, separate action expertLarge-scale pretraining and continuous action generation
SmolVLALightweight flow matching action expertSmall model, efficient inference

OpenVLA is the starting point of this progression. Its architecture is the most intuitive, and what the next three models changed is best seen against it.

2Architecture: Using a VLM Directly as the Policy

OpenVLA is a VLM called Prismatic-7B fine-tuned on robot data. There is no separate network for producing actions. It predicts the next action token the way a language model predicts the next word in a sentence.

There is a reason for using two vision encoders. The paper explains that DINOv2 helps with spatial reasoning. In a comparison experiment that removed DINOv2, the average success rate fell from 45.6% to 40.6%, a drop of about 5 points (Bridge-data-only model, Appendix D).

3Splitting Continuous Actions into 256 Bins

All a language model can output is tokens in its vocabulary, so continuous actions have to be turned into tokens. OpenVLA divides each dimension of the 7-dimensional action into 256 bins.

The bins span the range between the 1st and 99th percentiles of the action values in the training data. The earlier RT-2 used the minimum and maximum, but then a single outlier can widen the bins and lower the resolution. Using percentiles reduces this problem.

Take a value normalized to [-1, 1] as an example. One bin has width \(2/256 \approx 0.0078\). The value 0.173 falls into the following bin.

$$k = \left\lfloor \frac{0.173 + 1}{2} \times 256 \right\rfloor = \lfloor 150.14 \rfloor = 150$$

Instead of outputting the real number 0.173, the model picks "bin 150." Mapping back to the center of the bin gives about 0.176, and the error this scheme introduces is at most half a bin width, about 0.004. In the paper's data the bin width is set by each dimension's percentile range, so the numbers differ, but the principle is the same.

The implementation has one minor but fun problem. The Llama tokenizer reserves only 100 special tokens, which cannot hold 256. OpenVLA overwrites the 256 least used tokens at the end of the vocabulary with action tokens.

4Training Is Next-Token Prediction

At this point, training is almost the same as fine-tuning a language model. The input is the image and the instruction, and the target is the sequence of action tokens. The loss is the usual next-token cross-entropy, computed only over the action tokens.

$$\mathcal L = -\sum_{i=1}^{7} \log p_\theta\!\left(k_i \mid I, l, k_1, \ldots, k_{i-1}\right)$$

It is worth pointing out that this does not mean instructing the robot through a prompt to "move your joints like this." What changed is the vocabulary, the labels, and the data.

The last row matters. The experiment with a frozen vision encoder had an average success rate of 46.7%, far below the 80.0% obtained when it was trained jointly (this is an ablation result with a small sample). This means that simply reusing the VLM's visual features as they are is not enough for robot control.

5Attention and Autoregressive Generation

Let's follow what happens inside the transformer using "pick up the red cup." Image patches and words all become vectors, that is, tokens. Each token produces three vectors. Query is "the information I am looking for now," Key is "the information I am related to," and Value is "the information I actually pass along."

$$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V$$

\(QK^\top\) computes the relevance between tokens, softmax turns it into weights, and the Values are then summed with those weights. If training goes well, the Query of the token "red" can score highly with the Keys of the image patches covering the red cup. Nobody programmed that in, though. Relations useful for the task simply form through training.

\(M\) is the attention mask, which effectively pushes the scores of positions that cannot be seen infinitely low. This mask keeps OpenVLA's language model from seeing later tokens that have not been generated yet. That is why an action is produced one token at a time.

$$P(a_1,\ldots,a_7\mid I,l)=\prod_{i=1}^{7}P(a_i\mid I,l,a_1,\ldots,a_{i-1})$$

The training data already contains the future answers, so why hide them? The answers are still used. They are used to compute the loss, and are only withheld from the input that produces the prediction.

To avoid confusion, the feedback involved here should be split into two kinds.

  • Autoregressive feedback: Previously generated outputs serve as conditions for the next output within the same prediction.
  • Control feedback: The result of the robot's action is newly observed and reflected in the next prediction.

The second kind is present unchanged in the parallel prediction model of Part 2. The difference lies in the first. And sequential prediction does not mean the joints move one at a time. The robot executes the completed action vector after all 7 tokens have been produced.

OpenVLA's inference cost comes from a structure that runs the language model once per action dimension.

7Limitations and the Next Part

Putting together the limitations the paper itself names and those that follow from the architecture gives the following list.

  • The input is a single image only. It does not take a wrist camera, robot state (proprioception), or observation history.
  • It is slow. It runs at about 6Hz on a single RTX 4090. That falls far short of bimanual systems like ALOHA that run at 50Hz.
  • Trajectory smoothness. On precise tasks within a narrow range, Diffusion Policy produces smoother trajectories.
  • Reliability. Success rates on the evaluation tasks are generally below 90%.

The paper mentions action chunking as a solution for fast control. OpenVLA-OFT in Part 2 goes exactly in that direction, keeping the same backbone and removing the token generation scheme.
