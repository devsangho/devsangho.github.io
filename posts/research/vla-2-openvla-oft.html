OFT stands for Optimized Fine-Tuning. It is not a new pretrained model. It is a fine-tuning recipe that keeps the 7B-scale OpenVLA as it is and changes the output side. Yet this change alone raised the average LIBERO success rate from 76.5% to 97.1%.

OFT bundles several changes together, so it is easy to lose track of which one had which effect. Let's separate three things at the start: whether the input includes the robot state, whether the action representation is discrete tokens or continuous real values, and whether the generation method is sequential or parallel. These three are independent design choices.

1Action Chunking: Changing the Learning Problem

Action chunking groups several future actions into a single prediction unit. If you predict a 7-dimensional action for 10 timesteps (as an example), the output changes from one vector to a matrix.

$$A_t=\begin{bmatrix}a_t\\a_{t+1}\\\vdots\\a_{t+9}\end{bmatrix}\in\mathbb R^{10\times7}$$

This does not mean telling the model in a prompt to "output 10 actions as a group." What changes is the output structure and the training labels. The ground truth is simply cut longer from the same demonstrations in the dataset.

$$(o_t,l)\to a_t$$ $$(o_t,l)\to [a_t,a_{t+1},\ldots,a_{t+9}]$$

The model now learns "how things will continue" instead of "what to do now." In practice, the paper uses \(K=8\) on LIBERO and \(K=25\) on ALOHA.

The predicted length and the executed length are separate. You can predict 10 actions, execute only the first 3, and then observe again. In that case the chunk horizon is 10 and the replanning interval is 3. Looking again more often responds better to changes in the environment, but inference has to run more often. The OFT paper executed each predicted chunk open-loop to the end.

2Parallel Decoding: Not Waiting for Earlier Values

The difference between the sequential and parallel approaches reduces to one question. Do you need the first predicted value in order to compute the second one?

The implementation works like this. In the input slots that used to hold previous actions, you put empty action embeddings that differ only in their positional encoding. The causal mask is replaced with bidirectional attention. The language model then produces representations for all action positions in one forward pass. To lengthen the chunk, you add more empty embeddings.

CorrectionAt first it is easy to read this as "one VLM hidden state goes into an MLP, which produces 70 numbers that are reshaped to 10×7." That is not a bad explanation of the principle, but it differs from the actual architecture. In the paper's OFT, an empty embedding goes in at each action position, and these positions see the image, the language, and the other action positions through bidirectional attention inside Llama before going to the MLP. So the explanation that "an MLP head cannot handle relationships between actions with attention" also does not apply to OFT as stated. The attention has already happened in the language model before the MLP.

Two points need care. Predicting in parallel does not remove the relationships between actions, because the model learns temporal patterns by fitting the ground-truth sequence jointly. Also, parallel prediction does not mean parallel execution. The robot executes the resulting actions in temporal order.

3Continuous Actions and Regression

Regression outputs continuous numbers directly instead of picking one of 256 bins. OFT replaces the output embedding layer with a 4-layer MLP (ReLU) and trains it to minimize the mean L1 error on normalized actions.

$$\mathcal L=\frac{1}{K}\sum_{k=0}^{K-1}\left\|\hat a_{t+k}-a_{t+k}\right\|_1$$

Regression and action chunking are different concepts. Regression is about the training objective and the output format, while chunking is about how many future actions are predicted together. Either one can be used without the other.

Going deeper: one training step with small numbers

Consider an input \(h=[0.5,0.8]\), a target \(a^*=[0.3,0.7]\), and a linear layer \(\hat a=Wh\). With \(W=\begin{bmatrix}0.2&0.1\\0.4&0.3\end{bmatrix}\), the prediction is \([0.18,0.44]\).

$$L=\frac{(0.18-0.3)^2+(0.44-0.7)^2}{2}=0.041$$

The gradient with respect to \(W_{11}\) is \((0.18-0.3)\times0.5=-0.06\). It is negative, so increasing this weight reduces the loss. With a learning rate of 0.1, \(W_{11}\) goes from 0.2 to 0.206. The same thing happens in a head that outputs 70 numbers. The error at the fifth timestep also backpropagates through the shared weights, and as the errors at the various timesteps shrink together, the model learns the pattern of the action sequence.

An MLP does not inherently know which 7 outputs belong to which timestep. The meaning is set when the loss is computed, by comparing each output position with the ground truth for its timestep.

Why L1 and Not Diffusion

The paper also compared a diffusion head. On LIBERO-Long, L1 reached 90.7% and diffusion (50 steps) reached 91.1%, which is nearly the same. But the latencies were 0.0729 seconds and 1.9070 seconds, a 26x difference. Reducing the inference steps makes it faster but lowers performance, to 85.7% at 2 steps and all the way to 0% at 1 step.

CorrectionThe explanation that "direct regression averages the two paths" applies to MSE. OFT uses L1, so it goes toward the median rather than the conditional mean. The paper also writes that L1 can mitigate noise by learning the median mode. Even so, if demonstrations turning left and turning right are mixed half and half, the problem of not settling on either path remains. The paper acknowledges that L1 can be weak on this kind of multimodal behavior. This problem is the topic of Part 3.

4Added Inputs: Wrist Camera and Robot State

Robot state (proprioception) is information about the robot's own body, such as joint angles and whether the gripper is open or closed. These values are hard to determine from cameras alone. OFT projects this state through a 2-layer GELU MLP and feeds it in as one input embedding.

Each image produces 256 patch embeddings, so adding a wrist camera grows the visual tokens from 256 to 512. The image and state embeddings are concatenated along the sequence dimension. This change does not disturb the existing OpenVLA pipeline much.

$$\hat A_t=\pi_\theta(I^{\text{3rd}}_t,I^{\text{wrist}}_t,l,s_t)$$

Latency does rise from 0.0729 seconds to 0.1120 seconds, though. That is the price of more input tokens.

5OFT+: Tying Language to Visual Features with FiLM

A different problem appeared in the ALOHA bimanual tasks. When the policy receives multiple viewpoints including the wrist camera, it leans on visual correlations and ignores the language command. Without FiLM, the language-following rate on the last two tasks was 33%, the level of choosing a command at random.

The solution is FiLM (Feature-wise Linear Modulation). Two vectors, \(\gamma\) and \(\beta\), are generated from the mean of the task command embeddings and used to modulate the visual features.

$$\hat F=(1+\gamma)\odot F+\beta$$

FiLM is inserted in each transformer block of both SigLIP and DINOv2, after self-attention and before the feedforward layer. \(\gamma\) and \(\beta\) do not differ by patch. Per hidden dimension, the same value is applied to all patches. The paper reports that modulating each patch differently actually made language following worse. Because \(\gamma\) and \(\beta\) start near 0, the \((1+\gamma)\) form preserves the pretrained activations early on.

FiLM was used only in OFT+, meaning the ALOHA experiments. On LIBERO its effect was small (97.0% vs. 96.8%). The paper itself says it is unclear why OpenVLA's language grounding is weak only on ALOHA.

7Limitations and the Next Part

  • Multimodal behavior. L1 may fail to represent the multiple paths in the demonstrations. Conversely, the paper says diffusion risks overfitting to poor modes.
  • Pretraining scale. OFT is a recipe for the fine-tuning stage. Whether the effect holds under large-scale pretraining, and whether diffusion is still unnecessary in that case, has not been verified.
  • Language grounding. Why language following varies by task has not been explained.

One question remains here. How do we handle situations where the same input can have several correct answers? Rather than dropping regression, π0 in Part 3 changes what is being regressed.
